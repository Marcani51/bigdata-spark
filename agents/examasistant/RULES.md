# RULES.md

## Project Coding & Writing Rules for Big Data Assignment

This document defines strict rules for generating content for the Big Data Analytics assignment.

All outputs MUST follow these rules.

---

## 1. General Writing Rules

- Language: Bahasa Indonesia (formal akademik)
- Tone: Objektif, analitis, dan profesional
- Avoid:
  - Opini tanpa dasar
  - Kalimat terlalu santai
  - Penjelasan dangkal

---

## 2. Structure Rules (MANDATORY)

Output MUST follow:

### Bab 1 – Pendahuluan

- 1.1 Latar Belakang Masalah
- 1.2 Market dan Business Drivers
- 1.3 Pemangku Kepentingan

### Bab 2 – Rancangan Solusi Big Data

- 2.1 Metode Pengumpulan Data
- 2.2 Teknologi Penyimpanan Data
- 2.3 Processing Framework

### Bab 3 – Tata Kelola IT

- 3.1 Security
- 3.2 Compliance
- 3.3 Data Privacy
- 3.4 Data Quality

### Bab 4 – Data

- 4.1 Deskripsi Data
- 4.2 Model Data

---

## 3. Content Rules

### MUST include:

- Real-world problem (retail domain)
- Clear business justification
- Big Data architecture explanation
- Data type classification:
  - Structured
  - Semi-structured
  - Unstructured

---

## 4. Technology Rules

When mentioning technologies, MUST include:

- Reason for choosing it
- Role in architecture

Example:

- Apache Spark → for distributed data processing
- Kafka → for streaming ingestion

---

## 5. Data Rules

- Must describe dataset fields
- Must explain:
  - Data format (CSV, JSON, etc.)
  - Data characteristics (volume, variety)

---

## 6. Governance Rules

Each must include explanation:

- Security → encryption, access control
- Compliance → GDPR / UU PDP
- Privacy → anonymization
- Data Quality → cleaning, validation

---

## 7. Explanation Depth Rules

Each section MUST:

- Explain "what"
- Explain "why"
- Explain "how"

---

## 8. Formatting Rules

- Use numbering (1.1, 2.1, etc.)
- Use paragraphs (not bullet only)
- Tables allowed for clarity
- Avoid excessive lists

---

## 9. Consistency Rules

- Same terminology throughout document
- Do not switch context (stay in retail domain)
- Do not introduce unrelated topics

---

## 10. Output Quality Standard

A valid output MUST:

- Be logically connected
- Be academically sound
- Be ready for submission with minimal editing

## 11. tools

- Use `python` for coding
- Use `mermaid` for diagrams
- Use `markdown` for formatting
- Use `banana nano` for creating picture

---

## ❌ Invalid Output Examples

- Only listing tools without explanation
- Missing subsections
- Too generic (e.g., "Big Data is important")

---

## ✅ Valid Output Examples

- Clear explanation of retail problem
- Justified architecture design
- Detailed data description
